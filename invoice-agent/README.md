# invoice-agent (milestones B1 + B2 + B3)

Reads invoice PDFs locally, pulls out the key fields, flags anything a
human should check, and spots invoices that were sent twice (B1). An n8n
workflow then runs each invoice end to end: duplicate check, payment
status from a **mock** accounting API, a reminder draft for unpaid and
overdue invoices, a human approve/reject step, and an error workflow (B2).
Everything runs on your own machine. No cloud services, no paid APIs.
**Nothing is emailed**: approved reminders are only written to a local
file.

All invoices here are **synthetic**: made-up companies, numbers and
amounts, generated by `synthetic/generate_invoices.py`.

## What it does

| Part | File | What it does |
|---|---|---|
| PDF reading | `extractor/pdf_text.py` | pdfplumber text (plain and layout mode) and tables; detects a missing text layer |
| Fields | `extractor/fields.py` | One function per field: vendor, invoice_number, invoice_date, due_date, currency, line_items, subtotal, tax, total. Each returns value + confidence |
| Checks | `extractor/validate.py` | Flags: `missing_<field>`, `low_confidence_<field>` (< 0.7), `totals_mismatch`, `due_before_invoice_date`, `no_text_layer`. `needs_review = bool(flags)` |
| Duplicates | `extractor/duplicates.py` | Key = normalised vendor + invoice number + total (2 dp), stored in SQLite (`data/duplicates.db`) |
| Extractor API | `extractor/api.py` | FastAPI on port 8101 |
| Mock accounting | `mock_accounting/api.py` | **MOCK** QuickBooks-style API on port 8102 with **fake data** |
| Accuracy | `scripts/accuracy_report.py` | Compares extraction with `synthetic/expected.json` |

### Confidence rule

- `1.0` value found next to an expected label (e.g. `Invoice No:`)
- `0.6` no label; a fallback pattern found it (e.g. vendor from the letterhead line)
- `0.0` not found. The value stays `None`. Nothing is guessed.

Money fields (subtotal, tax, total) and the due date have **no fallback**:
a guessed total or due date is worse than a missing one.

### Dates

Dates are returned as ISO `YYYY-MM-DD`. Accepted: `2026-10-03`,
`03/10/2026`, `3 Oct 2026`. A slash date where both parts are 12 or less
(`03/10/2026`) is ambiguous; the extractor **assumes dd/mm** and lowers the
confidence to 0.6, so the invoice is flagged for review. If one part is
above 12 (`28/10/2026`) the order is clear and confidence stays at 1.0.

### Why not AWS Textract

Textract is not used. It is only available on the AWS Paid plan for new
accounts (checked 20 Nov 2026), and this project is $0 only. B1 uses
pdfplumber, which needs a text layer; scanned or image-only PDFs are
flagged `no_text_layer` instead of being read.

## Run it

```
cd invoice-agent
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
copy .env.example .env

.venv\Scripts\python synthetic\generate_invoices.py   # rebuild the 12 PDFs + expected.json
.venv\Scripts\python -m pytest -q
.venv\Scripts\python scripts\accuracy_report.py

.venv\Scripts\python -m extractor.api          # http://127.0.0.1:8101
.venv\Scripts\python -m mock_accounting.api    # http://127.0.0.1:8102 (MOCK)
```

### Extractor API (port 8101)

- `GET /health`
- `POST /extract` with either
  - multipart upload, form field `file`, or
  - JSON `{"path": "inv_01.pdf"}`; the path must be inside `INBOX_DIR`
    (paths outside it get 403)

  Returns `file_id`, `fields`, `confidences`, `flags`, `needs_review`.
- `POST /check-duplicate` with JSON
  `{"file_id", "vendor", "invoice_number", "total"}` returns
  `{"duplicate": bool, "original": file_id or null}`. The first time a key
  is seen it is stored.

### Mock accounting API (port 8102)

**This is a mock with fake data.** It does not connect to QuickBooks or
any real accounting system. Payment records in `mock_accounting/data.json`
are invented for the synthetic invoices.

- `GET /invoices/{invoice_number}/payment-status` returns
  `{"status": "paid" | "unpaid" | "partial", "amount_paid", "mock": true}`;
  unknown numbers return 404.
- Every response carries the header `X-Mock: true`.

## The synthetic invoices

12 PDFs in `synthetic/invoices/`, 4 layouts (classic ruled table,
two-column, letterhead with `Inv No.` labels and an unruled table, narrow
receipt), currencies USD / EUR / GBP / PKR. Special cases:

- `inv_09_resent_copy.pdf`: same vendor, number and total as `inv_01`
- `inv_10_no_due_date.pdf`: no due date printed
- `inv_11_malformed.pdf`: table cut off mid-row, no subtotal/tax, total printed as `##.#?`
- `inv_12_image_only.pdf`: the page is a picture, no text layer

The generator is deterministic (no randomness; reportlab invariant mode).
Re-running it produced byte-identical files on the machine it was tested on.

## What was not tested

- Real-world invoices from real vendors (none were used)
- Scanned PDFs / OCR (not implemented; image-only PDFs are only flagged)
- Multi-page invoices, non-English invoices, comma-decimal amounts (`1.234,50`)
- Airtable and AWS: those are later milestones (B3, B4)
- Load, concurrency or security review of the APIs beyond the inbox path check

## B2: n8n workflow with human approval

Full instructions: [`docs/N8N.md`](docs/N8N.md). Short version:

```
copy .env.example .env     # then put a random N8N_ENCRYPTION_KEY in .env
docker compose up -d --build
powershell -ExecutionPolicy Bypass -File scripts\n8n_setup.ps1
.venv\Scripts\python scripts\run_inbox.py
.venv\Scripts\python scripts\review.py list
.venv\Scripts\python scripts\review.py approve 1
docker compose down
```

| Part | File |
|---|---|
| Stack (api, mock-accounting, n8n `2.48.7`) | `docker-compose.yml`, `Dockerfile` |
| Workflows | `n8n/workflows/invoice_intake.json`, `n8n/workflows/invoice_errors.json` |
| Import + publish | `scripts/n8n_setup.ps1` |
| Export + clean | `scripts/n8n_export.ps1`, `scripts/sanitize_workflow.py` |
| Send invoices | `scripts/run_inbox.py` |
| Human review CLI | `scripts/review.py` (`list`, `show ID`, `approve ID`, `reject ID`) |
| Live check | `scripts/e2e_n8n.py` |
| Reminder text | `extractor/reminders.py` (`draft_reminder`) |
| Review queue (SQLite `data/review.db`) | `extractor/review_queue.py` |

New extractor API endpoints: `GET /inbox`, `POST /drafts`,
`GET /drafts?status=`, `GET /drafts/{id}`, `POST /drafts/{id}/decision`,
`POST /outcomes`, `GET /outcomes`, `POST /errors`, and `POST /demo/reset`
(off unless `DEMO_RESET_ENABLED=true`, used by the e2e script). `/extract` now also
returns `blocking_flags` and `stop_for_review`.

The reminder is an internal note to the accounts payable team of
"Fernhill Trading Co", a made-up company (these invoices are bills we
received). Approved reminders go to `outbox/approved_reminders.jsonl` with
`"sent": false`.

### Design choice: which flags stop the workflow

The plan said "needs_review -> stop". With that rule 8 of 12 invoices
stop, because low-confidence flags are common on these layouts, and no
invoice at all would reach the approval step. So the workflow stops only
on **blocking** flags (`missing_*`, `no_text_layer`, `totals_mismatch`,
`due_before_invoice_date`). Low-confidence flags do not stop it; they are
stored with the draft and shown by `review.py list`, so the human sees
them before approving. `needs_review` itself is unchanged.

## B3: results copied to Airtable

`scripts/sync_airtable.py` copies what an n8n run left behind into an Airtable base
(schema in `docs/AIRTABLE_SCHEMA.md`): one row per invoice in `Invoices`, the reminder
drafts with their pending / approved / rejected status in `Reminder Drafts`, and failures
from the error workflow in `Error Log`.

```
.venv\Scripts\python scripts\sync_airtable.py --dry-run   # build rows, no API calls
.venv\Scripts\python scripts\sync_airtable.py             # schema check, then upsert
```

- `airtable_sync/client.py`: `AirtableClient` (httpx, Web API v0) and `FakeAirtableClient`.
  At most 10 records per request, a short pause between requests, and a call counter.
- Writes are **upserts** on a key field (`File`, `Draft id`, `Received at`), so a second run
  updates rows instead of duplicating them.
- Before writing anything it reads the base schema (1 call) and stops if a table or field
  is missing or has the wrong type.
- The sync runs as a script after the workflow, not as an n8n node, so no Airtable token is
  stored in n8n or in the exported workflow JSON (see `../docs/DECISIONS.md` #16).

### What was tested (B3, 21 Nov 2026)

- `tests/test_airtable_sync.py` (9 tests, fake client, zero API calls): batching, schema
  check, outcome labels, row building from real synthetic PDFs, upsert twice without
  duplicates, dry run makes no client, request body of the real client, error handling.
  Whole suite: `185 passed`.
- Live, on a free Airtable base: a fresh n8n run (`scripts/e2e_n8n.py`, 11/11 checks), then
  the sync. Result: 12 created in `Invoices` (3 paid, 2 not overdue, 3 draft created,
  3 needs review, 1 duplicate), 3 in `Reminder Drafts` (1 pending, 1 approved, 1 rejected),
  1 in `Error Log`. A second sync: 0 created, 16 updated.
- Airtable API calls used on 21 Nov 2026: 14 in total (1 schema check before coding,
  5 per sync run x 2, 3 to read the rows back). Free plan allows 1,000 per month.

### What was not tested (B3)

- The sync is run by hand after the workflow; it is not triggered by n8n.
- Rows removed locally (for example after `/demo/reset`) are not deleted from Airtable.
  Draft ids restart at 1 after a reset, so `draft-1` is overwritten by the next run's draft 1.
- Only the 12 synthetic invoices, one base, one user.
